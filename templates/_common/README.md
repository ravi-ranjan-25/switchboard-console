## How it gets deployed

```
git push origin main
  -> GitHub Actions (.github/workflows/build.yml): tests, then builds the arm64 image
     and pushes ghcr.io/[[.Owner]]/[[.Repo]]:<UTC timestamp>-<sha7>   (private package)
  -> Flux image automation in the citadel repo notices the newest tag (about 10 minutes)
     and commits it to apps/[[.Name]]/deployment.yaml
  -> Flux applies the commit and the pod rolls
```

The Kubernetes manifests (Deployment, Service, Flux Kustomization, exposure, backups) are **not** in this repo. Switchboard generated them in the
citadel repo (`apps/[[.Name]]/` and `clusters/keep/apps/[[.Name]].yaml`). Change exposure, replicas, tag rollback or delete from the Switchboard console.

First deploy: the app starts with **replicas 0** until the first image exists. After the first green run of *Build image*, switch the app on in Switchboard.

## Configuration and secrets

* Plain settings are environment variables in the app's Deployment (edit in the citadel repo).
* Secrets are never committed. Declare their **names** in Switchboard (New app > Secret names); the values live in the OCI Vault (`make secret` in the citadel repo).
  `.env.example` documents local-only values.
* The container runs as a non-root user and needs no write access outside `/tmp`.
